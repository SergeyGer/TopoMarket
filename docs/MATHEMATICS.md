# TopoMarket mathematics reference (v1.2)

This is the corrected, versioned reference for the mathematics behind TopoMarket's daily price
signal, industry views and warning evaluation. It supersedes the earlier mathematical-framework
draft. The equations describe the frozen release contract; implementation and test links follow the
relevant sections.

## 1. Scope and claim contract

TopoMarket asks whether a change in the shape of S&P 500 returns can warn of a 10% decline within
20 sessions. **The early-warning claim is experimental.** The daily score ranks the deviation of
today's loop persistence from its recent median against the previous deviations. It is not an
estimated crash probability, odds, expected loss or confidence level, and the pipeline estimates no
such quantity.

The current public evidence is deliberately small and weak. On the bundled synthetic holdout there
are 3 evaluable episodes; the TDA policy warned before **0 of 3** episodes, the VIX comparison
before **1 of 3**, and realized volatility before **0 of 3**. On 3,306 common eligible sessions the
average precision is 0.0154 for TDA, 0.1187 for VIX and 0.0556 for realized volatility; all three
frozen policies select the 99th percentile. The evidence wording is `Experimental market anomaly`.
The linked report is the authority for these figures.

The label contract used everywhere in this document is:

| Contract field | Value |
| --- | --- |
| Target | A close at or below 0.90 times the origin close |
| Horizon | The next 20 index sessions (rows), inclusive |
| Pending | The horizon is not fully observed and no breach has occurred |
| Episode gap | At most 20 index sessions between distinct first-breach sessions |
| Warning lead | 1 to 20 index sessions before the episode onset |
| Credit rule | Positive own-origin label, breach owned by the matched episode, one credit per episode |

Feature construction uses only closes up to the signal close `t`. Future closes enter only the
evaluation target and are never inputs to the daily score. All quoted public numbers use the
synthetic showcase. Private historical aggregates, private reports and ledgers are kept outside the
public repository and are not published in this reference.

## 2. Price signal

### 2.1 Window and returns

Let `C_t` be the S&P 500 close on session `t`, and define the log return for that close as

$$
r_t = \log\left(\frac{C_t}{C_{t-1}}\right).
$$

For a signal dated `t`, the window is exactly the 60 log returns ending at `t`:

$$
W_t = \left(r_{t-59}, r_{t-58}, \ldots, r_t\right).
$$

The window is available only when all 60 values are finite and are consecutive valid returns in the
input table. A missing or non-finite return resets the valid run; the window stays unavailable until
60 new consecutive valid returns exist. There is no interpolation, forward fill, exchange-calendar
inference or use of a future row. A valid window has 60 observations and 60 only.

### 2.2 Robust scaling

Within the window, let

$$
m_t = \operatorname{median}\left(W_t\right),
\qquad
\operatorname{MAD}_t = \operatorname{median}_{r \in W_t}\left(\lvert r - m_t\rvert\right),
\qquad
s_t = 1.4826 \cdot \operatorname{MAD}_t.
$$

Scale every return in the window to

$$
z_i = \frac{r_i - m_t}{s_t}, \qquad i = t-59, \ldots, t.
$$

The constant 1.4826 is the usual normal-consistency factor that makes the MAD comparable to a
standard deviation; it is not an estimate of the standard deviation and it does not make the score
probabilistic. If `MAD_t = 0`, or if the median, MAD or scale is non-finite, the window is
**unavailable**. It is never converted into `L_t = 0`.

### 2.3 Delay coordinates

Write the 60 scaled values in window order as `z_0, ..., z_59`. For each position
`i = 4, ..., 59`, define the causal delay vector

$$
x_i = \left(z_i, z_{i-2}, z_{i-4}\right) \in \mathbb{R}^3.
$$

The number of points is

$$
N = 60 - (3 - 1)\cdot 2 = 56.
$$

The first vector is `(z_4, z_2, z_0)` and the last is `(z_59, z_57, z_55)`. The window is therefore
**60 returns, 56 points**, not 56 returns.

Any two-dimensional scatter of these points is a projection of the three-dimensional cloud. The
persistence computation uses all three coordinates.

**Implementation note.** The causal orientation above is the published coordinate convention. The
score pipeline's shared embedding primitive builds the forward-oriented cloud
`(z_j, z_{j+2}, z_{j+4})` for `j = 0, ..., 55`. Reversing coordinate order maps each forward vector
to the corresponding causal vector (`i = j + 4`), so all pairwise Euclidean distances and every
persistence lifetime are identical. The returned `L_t` is unaffected by the orientation.

### 2.4 Vietoris–Rips persistence

Take the full Euclidean point cloud `X_t = {x_4, ..., x_59}`. The Vietoris–Rips filtration contains
a simplex whenever every pair of its vertices is at distance at most the filtration scale
`epsilon`. Compute homology in dimensions `H_0` and `H_1` with coefficients in `GF(2)`, using a
complete filtration: no distance threshold and no point subsampling.

A persistence diagram interval is written as `[b, d)`, where `b` is the birth scale and `d` the
death scale. Its lifetime is

$$
\ell = d - b.
$$

Infinite deaths (including the essential `H_0` class) are excluded. Finite intervals with
`ell <= 1e-8` are also excluded; the comparison is strict, so a lifetime exactly equal to `1e-8` is
dropped. The diagrams are computed over every point in the 56-point cloud.

### 2.5 Loop statistic

Let `H_1^{(t)}` be the retained finite `H_1` lifetimes for the window at `t`. The daily loop
statistic is

$$
L_t =
\begin{cases}
\max\left(H_1^{(t)}\right), & H_1^{(t)} \neq \varnothing,\\
0, & H_1^{(t)} = \varnothing.
\end{cases}
$$

`L_t` is measured in the robustly scaled coordinate units defined in Section 2.2, so it is
dimensionless. A valid cloud with no retained loop has `L_t = 0` and contributes a normal value to
the histories. An invalid window has no `L_t` at all; its score remains null and it never enters a
reference history. The `h1_count` recorded beside `L_t` is the number of retained finite `H_1`
intervals, not the number of loops in the data.

## 3. Percentile score

### 3.1 Deviation and midrank

At close `t`, let `L_t` be the loop statistic from a valid window. Let

$$
D_t = \left\lvert L_t - \operatorname{median}\left(L_{t-252}, \ldots, L_{t-1}\right)\right\rvert
$$

where the reference consists of the **previous 252 valid** `L` values, excluding the current one.
The reference is a valid-observation history, not a calendar window: invalid windows are skipped.
`D_t` is computed only after 252 previous valid `L` values exist.

Let the previous 252 valid deviations be `D_(1), ..., D_(252)`. Define

$$
S_t = 100 \cdot \frac{\text{number below } D_t + 0.5 \cdot \text{number tied with } D_t}{252}.
$$

Comparisons use an absolute tolerance of `1e-12`:

- a reference value is **below** when it is less than `D_t - 1e-12`;
- a reference value is **tied** when its absolute difference from `D_t` is at most `1e-12`;
- otherwise it is above.

A tie contributes one half, which is the standard midrank. `S_t` is reported in score points on
`[0, 100]`. A score of 100 means every one of the 252 reference deviations is below `D_t` outside
the tie band; ties pull the score below 100. A score of 90 does not mean a 90% chance of a decline.

### 3.2 Warm-up, gaps and states

With uninterrupted valid returns and the frozen configuration, the first valid `L` is on the 60th
return (0-based row 59), the first `D` is on return `60 + 252 = 312` (0-based row 311), and the first
score is on return `312 + 252 = 564` (0-based row 563). Invalid windows postpone this sequence;
they do not consume a reference slot.

| State | Meaning |
| --- | --- |
| `unavailable` | Fewer than 60 consecutive valid returns, a missing or non-finite return, or a zero/non-finite robust scale |
| `warming_up` | A valid `L` exists but fewer than 252 valid `L` or 252 valid `D` references exist |
| `scored` | Both reference windows are full and `score` is in `[0, 100]` |

A `D` value enters the `D` history only when it was computed from a full 252-value `L` reference
set. Invalid windows and partial histories never enter either reference. When a gap ends, the prior
valid histories are still available; the earliest new `D` depends on how many valid values remain
before it.

### 3.3 Worked midrank check

If 189 earlier deviations are smaller than `D_t` and 6 tie with it, the remaining 57 of the 252
references are larger. The score is

$$
S_t = 100 \cdot \frac{189 + 0.5 \cdot 6}{252}
    = 100 \cdot \frac{192}{252}
    = 76.190476\ldots
$$

rounded for display to **76.19**. See [Section 7.2](#72-tied-midrank-gives-7619) for the standalone
arithmetic.

## 4. Interpretation caveats

- **Takens-inspired, not a theorem applied to markets.** The delay coordinates represent recent
  return patterns in the spirit of Takens' embedding idea. Applying the reconstruction theorem
  requires deterministic dynamics, an observable system, a sufficient embedding dimension and
  negligible noise. The observed equity series does not establish those assumptions, so the
  embedding is a representation choice, not a proven reconstruction of a hidden state.
- **A loop is a geometric feature at a scale.** A retained `H_1` interval means the scaled return
  cloud contains a hole over a range of distance scales. Its lifetime measures how long that hole
  persists in the filtration. It is not a crash signature, a drawdown meter or a causal mechanism.
- **The predictive value is empirical.** Whether unusual loop persistence precedes losses is the
  question tested by the chronological evaluation, not something implied by the topology. The
  public synthetic result is 0 of 3 episodes warned; that is a weak, descriptive result and not
  evidence of a working crash predictor.
- **No probability is estimated.** The score is a percentile-like rank within its own valid
  history. It is not calibrated to outcome frequencies, and the bootstrap intervals in the
  evaluation report apply to evaluation metrics, not to a live crash probability or to the score.

## 5. Graph definitions

Three different objects appear in the app. They share a 60-session industry window but are not
interchangeable. The correlation network selects the trailing 60 rows for which all 12 returns are
finite, so it can skip an incomplete row; the industry cloud and Mapper select the last 60 rows and
require all 12 values in each row, raising a readable error otherwise.

| View | Objects | Data per object | Mathematical output |
| --- | --- | --- | --- |
| Correlation network | 12 industry portfolios | 60 paired daily simple returns | Pearson threshold graph |
| Industry point cloud | 60 sessions | 12 scaled industry coordinates | `H_0`/`H_1` persistence and a 2-D PCA view |
| Mapper graph | 12 industry portfolios | 60 returns; lens and pairwise distances | Cover, clusters and overlap graph |

### 5.1 Correlation network

For portfolios `i` and `j`, take 60 paired daily **simple** returns
`x_(i,s) = P_(i,s)/P_(i,s-1) - 1` over the trailing 60 sessions. The Pearson correlation is

$$
\rho_{ij} =
\frac{\sum_{s=1}^{60}\left(x_{i,s}-\bar{x}_i\right)\left(x_{j,s}-\bar{x}_j\right)}
{\sqrt{\sum_{s=1}^{60}\left(x_{i,s}-\bar{x}_i\right)^2}
 \sqrt{\sum_{s=1}^{60}\left(x_{j,s}-\bar{x}_j\right)^2}}.
$$

The window requires all 12 returns to be finite on each of the 60 sessions. A pair is **undefined**
when either series has zero variance (or fewer than two observations). Undefined pairs are
reported separately and are never silently drawn as zero. There are

$$
\binom{12}{2} = 66
$$

unordered pairs. An edge is present when

$$
\rho_{ij} \ge 0.80,
$$

inclusive: exactly 0.80 qualifies, 0.799999 does not, and 0.800001 does. Report the qualifying
count `n/66`, the count of defined pairs, the list of undefined pairs, and the mean defined
correlation

$$
\bar{\rho} = \frac{1}{D}\sum_{\text{defined pairs }(i,j)} \rho_{ij},
$$

where `D` is the number of defined pairs. The network payload reports the pair tags and undefined
pairs; the Structure comparison layer reports the mean off-diagonal correlation over the defined
pair tags.

**Six-decimal tag versus full precision.** The mathematical cutoff above applies to the unrounded
Pearson value. The JSON pair tag stores `round(rho, 6)` for display, and the released network
builder applies the cutoff to that six-decimal tag. The two decisions disagree only for a true
value that is below 0.80 but rounds up to `0.800000` (for example 0.7999996). The normative rule in
this reference is the full-precision comparison; exact 0.80 qualifies under both. See
[Section 7.5](#75-exactly-080-qualifies) for the boundary table.

Implementation: [`network.py`](../src/topomarket/analysis/network.py) and the comparison summary in
[`structure.py`](../src/topomarket/ui/structure.py). Public test:
[`test_network.py`](../tests/test_network.py).

### 5.2 Industry point cloud

The same complete 60-session window is reshaped into **60 points in 12-dimensional industry-return
space**: one point per session, one coordinate per industry. Write `x_(s,j)` for the simple return
of industry `j` on session `s`. Each industry column is robustly scaled independently over the 60
sessions:

$$
z_{s,j} = \frac{x_{s,j} - m_j}{1.4826 \cdot \operatorname{MAD}_j},
\qquad
m_j = \operatorname{median}_{s}\left(x_{s,j}\right),
\qquad
\operatorname{MAD}_j = \operatorname{median}_{s}\left(\lvert x_{s,j} - m_j\rvert\right).
$$

A zero or non-finite column scale makes the cloud invalid; the app reports an error rather than
substituting zeros. Persistence is computed on the **full 12-dimensional** scaled cloud with the
same Euclidean Vietoris–Rips, `GF(2)`, `H_0`/`H_1` and lifetime rules as Section 2.4.

The two-dimensional view is a labelled PCA projection of the centered scaled cloud: the 60-by-2
matrix of scores on principal components `PC1` and `PC2`, with each point carrying its session
date. The projection explains part of the variance and is only a view; no persistence is computed
from the two PCA coordinates.

Implementation: [`industries.py`](../src/topomarket/analysis/industries.py). Public test:
[`test_industries.py`](../tests/test_industries.py).

### 5.3 Mapper graph

The Mapper view again treats the **12 portfolios as the objects**, each with 60 observations. Its
pairwise dissimilarity is the clipped correlation distance

$$
d_{ij} = \min\left(2, \max\left(0, 1 - \rho_{ij}\right)\right).
$$

There is no square-root distance variant. A constant portfolio makes the Pearson matrix undefined;
the Mapper builder reports an error instead of creating a graph from fabricated correlations.

The lens value for industry `i` is its annualised sample volatility over the 60 daily returns:

$$
\sigma_i = \sqrt{252}\cdot \operatorname{std}\left(x_{i,1}, \ldots, x_{i,60}; \mathrm{ddof}=1\right).
$$

The lens is measured per year. Let `sigma_min` and `sigma_max` be the smallest and largest lens
values and let `Delta = sigma_max - sigma_min`. If `Delta = 0`, the cover is the single interval
`[sigma_min, sigma_max]`. Otherwise the closed cover has three intervals of width

$$
w = \frac{\Delta}{2.2}
\qquad\text{and stride}\qquad
s = 0.6\,w.
$$

For `k = 0, 1, 2`,

$$
I_k = \left[\sigma_{\min} + k s,\ \sigma_{\min} + k s + w\right],
$$

with the final upper endpoint clamped to `sigma_max` (in this construction it already equals
`sigma_max` because `sigma_min + 2s + w = sigma_max`). The intervals are **closed**: a lens value
exactly at an endpoint belongs to both adjacent intervals, and a boundary value can therefore be a
member of two bands. The overlap is 40% of the width.

For each interval, take its member industries and the submatrix of `d_ij`. Cluster the members with
connected components at

$$
d_{ij} \le 1.0,
$$

inclusive; an isolated industry is a singleton component. Each component is a Mapper node. The same
member set can occur in more than one interval; identical member sets are merged into one node and
the lowest interval index is kept as the deterministic representative. Nodes are therefore clusters
of industries, not intervals.

Two distinct nodes are connected when their member sets intersect. The edge records the shared
industries and their count. This overlap graph is the **1-skeleton of the nerve** of the cover: it
has nodes and edges, and no higher-dimensional simplices are drawn. The app displays these
overlap edges, with the shared portfolio names available on inspection.

Implementation: [`mapper.py`](../src/topomarket/analysis/mapper.py). Public tests:
[`test_mapper.py`](../tests/test_mapper.py).

## 6. Decision and uncertainty

### 6.1 Target labels

For an origin close `C_t`, the target is positive when the first close at or below 90% of the origin
occurs within the next 20 closes:

$$
y_t = 1
\quad\Longleftrightarrow\quad
\exists\, s \in \{1, \ldots, 20\}
\text{ such that }
C_{t+s} \le 0.90\,C_t.
$$

The first such `s` is the **first-breach session** for that origin. The comparison is inclusive: a
close exactly at 90% is a breach, and a floating-point guard of `1e-15` prevents an exact boundary
value from being lost to representation error. Day 20 is inside the horizon; day 21 is outside. If
no breach is observed and the full 20-session horizon has been observed, the label is 0. If no
breach is observed and the horizon extends past the last available row, the label is **pending**
(`None`), never negative, and is not used as a negative example.

The horizon and all lead/gap quantities are counted in index sessions (rows), not calendar days.
Consecutive rows are consecutive sessions by the input contract; the code infers no exchange
calendar.

### 6.2 Breach episodes

Take the distinct first-breach sessions from positive origin labels and sort them. Chain two
consecutive breach sessions into the same episode when their gap is at most 20 index sessions. A
gap of 21 or more starts a new episode. The episode onset is its earliest first-breach session and
the episode end is its latest. Each positive origin whose first breach is in the episode is recorded
as a positive origin of that episode.

### 6.3 Qualifying warnings and credit

An alert at session `a` is credited to an episode with onset `o` only when all three conditions
hold:

1. the alert's **own** origin label is positive, with first breach `b(a)`;
2. `b(a)` belongs to that episode's breach sessions; and
3. `1 <= o - a <= 20`, so the warning is 1 to 20 sessions early.

An episode is credited at most once. Later alerts that would claim an already-credited episode are
`duplicate`. An alert at or after an episode onset but inside the episode's breach span is
`post_onset` (the late category) and is not early-warning credit. Alerts whose own horizon is still
unobserved are `pending`; mature alerts that are not credited are `false_mature` and enter the
false-alert count. Episodes with no qualifying alert are `missed`. This strict rule is the
`label_positive_and_breach_owned` credit rule.

### 6.4 Periods, calibration and alert policy

The chronological split is:

| Period | Dates | Use |
| --- | --- | --- |
| Development | 1990-01-01 to 2004-12-31 | Development and description; no threshold is fitted here |
| Fitting (validation) | 2005-01-01 to 2013-12-31 | Percentile selection and frozen policy fitting |
| Holdout (test) | 2014-01-01 to the last mature origin | Out-of-sample evaluation only |

The final 20 validation sessions (the 20-origin purge) are excluded before selection; readings
after that boundary and episodes beginning after it are not eligible for calibration. The public
showcase records `purged_validation_sessions = 20`.

For each method, construct a candidate cutoff from each percentile in

$$
\{85,\ 90,\ 92.5,\ 95,\ 97.5,\ 99\}
$$

of that method's own eligible validation readings, using the linear-interpolation sample
percentile. For TDA the readings are the scored daily values; for VIX they are the `vix_close`
values; for realized volatility they are

$$
\widehat{\sigma}_t = \sqrt{252}\cdot
\operatorname{std}\left(r_{t-19}, \ldots, r_t; \mathrm{ddof}=1\right),
$$

where the returns are the 20 most recent log returns through `t`. This volatility is annualised
and uses the sample standard deviation (`ddof = 1`). VIX is a close in index points and is not
annualised.

Selection replays the same labels, episodes and credit rule on the validation period and orders
candidates by:

1. maximum episode recall, subject to at most 2 false alerts per year;
2. then fewer false alerts;
3. then the higher cutoff.

The paired comparison uses the stronger of the two simple comparators, VIX and realized volatility,
under the same validation ordering; the report records which one was selected.

If no percentile candidate satisfies the false-alert constraint, the method is recorded as a
**silent policy**: `calibrated = false`, `silent = true`, no cutoff and no percentile. A silent
policy emits no alerts; the method is still reported with its average precision and the reason is
recorded.

For a non-silent policy, an alert is emitted on a reading whose value is **at or above** the frozen
cutoff. After an alert, further alerts are suppressed until the session offset is at least 20; an
alert exactly 20 sessions after the previous one is allowed. Each policy is frozen with a hash that
binds the method, cutoff, percentile, cooldown, window, annualization, validation period, session
digest and eligible-year denominator.

### 6.5 Metrics and the comparable-date denominator

All compared methods are evaluated on the same **common eligible dates**: the intersection of the
dates on which every compared method has a finite reading, the target label is mature, and the date
lies in the holdout period. Let this count be `N_eligible`. The comparable-date denominator is

$$
\text{eligible years} = \frac{N_{\text{eligible}}}{252},
\qquad
\text{false alerts per year} = \frac{F}{N_{\text{eligible}}/252},
$$

where `F` is the number of false-mature alerts on those dates. It is not a calendar-year count and
not each method's own coverage.

Episode recall is the number of distinct credited episodes divided by the number of episodes whose
onset lies in the holdout period; one credit per episode. Report the numerator and denominator,
median lead with its minimum and maximum, and false alerts per year.

Average precision (AP) uses the **complete eligible scored daily series**, not only the alert
dates. Every eligible session with a mature label contributes a score and a binary label. Sort by
descending score and let a **tied-score block** contain every session sharing the exact same score.
For block `k`, let `n_k` be its size, `p_k` its positives, `N_k` the cumulative size, `TP_k` the
cumulative positives and `P` the total positives. Then

$$
\mathrm{AP}
= \sum_k \left(R_k - R_{k-1}\right) \mathrm{Prec}_k,
\qquad
\mathrm{Prec}_k = \frac{TP_k}{N_k},
\qquad
R_k = \frac{TP_k}{P},
\qquad
R_0 = 0.
$$

Ties are evaluated together: the whole block enters before its precision is taken. This is the
standard tied-score average precision (the value returned by `sklearn.metrics.average_precision_score`).
For example, with scores 0.9 (positive), 0.5 (positive), 0.5 (negative) and 0.1 (negative), the top
item contributes `0.5` and the tied block at 0.5 contributes `1/3`, so `AP = 5/6 = 0.8333...`.
If `P = 0`, AP is undefined and the report records `null` with the reason and the scored-session and
positive counts. Event prevalence is `P / N_scored`. Undefined values are explicit `null`; counts
that explain them are reported.

### 6.6 Bootstrap uncertainty (v2)

The reported uncertainty is a paired moving-block bootstrap over the ordered common eligible test
positions `1, ..., N`, with `N = N_eligible`. The algorithm identity is
`moving_block_with_replacement_v2`.

For `N >= 60`, the block length is `b = 60` contiguous eligible positions. Draw
`m = ceil(N / b)` blocks **with replacement** from the `N - b + 1` possible contiguous starting
positions, concatenate them and trim the result to exactly `N` positions. Every drawn position
keeps its multiplicity: if a position is drawn by several blocks, its weight is the number of
occurrences. The same draw and the same position weights are applied to every method and to all
indicator sets.

Let `w_p` be the multiplicity of position `p` after trimming. The exposure is always the fixed
`N` positions, so

$$
\sum_{p=1}^{N} w_p = N.
$$

For each method, let `O` be the set of holdout episode-onset dates, `M` the set of credited onset
dates and `F` the set of false-alert dates. The weighted counts are

$$
O_w = \sum_{p:\, s_p \in O} w_p,
\qquad
M_w = \sum_{p:\, s_p \in M} w_p,
\qquad
F_w = \sum_{p:\, s_p \in F} w_p.
$$

The replicate recall is `M_w / O_w` when `O_w > 0`, otherwise undefined; the replicate false-alert
rate is `F_w / (N/252)` using the fixed exposure. The recall gain is the primary recall minus the
comparator recall, and is defined only when both recalls are defined. The same weight vector is
used for both methods, which keeps the comparison paired.

Intervals are 95% percentile intervals of the replicate values (2.5% and 97.5% order statistics),
reported with the mean, valid-replicate count and total replicates. Intervals are computed only for
these five quantities:

| Interval | Defined when |
| --- | --- |
| `episode_recall_gain` | Both the primary and comparator recalls are defined |
| `tda_episode_recall` | The draw contains at least one onset |
| `comparator_episode_recall` | The draw contains at least one comparator onset |
| `tda_false_alerts_per_year` | Always, using the fixed `N` exposure |
| `comparator_false_alerts_per_year` | Always when a comparator is evaluated, using the fixed `N` exposure |

No intervals are reported for average precision, event prevalence, median lead or the raw score.
In the public showcase, the recall and gain intervals have 952 valid replicates of 1,000 because 48
draws contain no episode onset; the false-alert-rate intervals use all 1,000 replicates.

The v2 rule replaces the earlier set-based collection of drawn positions. A set discarded repeated
blocks, shrinking both the event counts and the effective sample; v2 keeps multiplicity and a fixed
`N` exposure. The identity string is stored in
`provenance.bootstrap_algorithm = moving_block_with_replacement_v2`.

Implementation: [`labels.py`](../src/topomarket/analysis/labels.py),
[`alerts.py`](../src/topomarket/analysis/alerts.py) and
[`evaluation.py`](../src/topomarket/analysis/evaluation.py). Public tests:
[`test_evaluation_labels.py`](../tests/test_evaluation_labels.py) and
[`test_evaluation_contract.py`](../tests/test_evaluation_contract.py).

### 7.1 60 returns give 56 points

### 7.2 Tied midrank gives 76.19

### 7.3 No H1 versus an invalid window

| Case | Window or cloud | Valid? | Retained H1 | `L` | Enters history? |
| --- | --- | --- | --- | --- | --- |
| No loop | Three collinear points `(0,0), (1,0), (2,0)` | Yes | none | `0.0` | Yes, as a normal zero |
| Zero MAD | 60 equal returns | No | not computed | `null` | No |
| Too short | 59 finite returns | No | not computed | `null` | No |

A valid cloud with no loop is not an error: it contributes `L = 0`. A zero-MAD or short window is
unavailable and contributes nothing. The distinction matters for warm-up counts and for the
reference histories.

```python
import statistics

returns = [0.001] * 60
center = statistics.median(returns)
mad = statistics.median(abs(value - center) for value in returns)
assert mad == 0.0  # zero scale -> unavailable, never L = 0
```

### 7.4 Closed cover endpoints

For a lens range `[0, 1]`, `w = 1/2.2 = 5/11` and `s = 0.6w = 3/11`. The three closed intervals are

| Interval | Lower | Upper |
| --- | --- | --- |
| `I_0` | 0 | 5/11 |
| `I_1` | 3/11 | 8/11 |
| `I_2` | 6/11 | 1 |

An endpoint is shared by both intervals that meet there:

| Lens value | Member of |
| --- | --- |
| 0 | `I_0` only |
| 3/11 | `I_0` and `I_1` |
| 5/11 | `I_0` and `I_1` |
| 6/11 | `I_1` and `I_2` |
| 8/11 | `I_1` and `I_2` |
| 1 | `I_2` only |

The intervals overlap by 40% of their width. A constant lens (`range = 0`) yields one interval,
`[value, value]`, not three degenerate copies.

### 7.5 Exactly 0.80 qualifies

```python
cutoff = 0.80
assert (0.80 >= cutoff) is True
assert (0.7999994 >= cutoff) is False
assert (0.800001 >= cutoff) is True
```

The boundary table separates the mathematical rule from the six-decimal display tag:

| True correlation | Six-decimal tag | Full-precision edge | Released tag comparison |
| --- | --- | --- | --- |
| 0.7999994 | 0.799999 | no | no |
| 0.7999996 | 0.800000 | no | yes |
| 0.8000000 | 0.800000 | yes | yes |
| 0.8000010 | 0.800001 | yes | yes |

Exactly 0.80 qualifies under both. The one divergent row is the implementation note in
Section 5.1; the reference rule is the full-precision column.

### 7.6 Day 20 breaches, day 21 does not

```python
closes = [100.0] * 22
closes[21] = 90.0

assert closes[21] == 90.0
assert closes[20] > 0.9 * 100.0
assert closes[21] <= 0.9 * 100.0
```

| Origin row | Future rows inspected | First breach | Label |
| --- | --- | --- | --- |
| 0 | 1 through 20 | none | 0, negative |
| 1 | 2 through 21 | row 21, day 20 | 1, positive |

For origin row 0 the fall at row 21 is day 21 and is outside the horizon. For origin row 1 the same
fall is day 20 and is inside it.

### 7.7 A forced duplicate bootstrap block keeps multiplicity

```python
from collections import Counter

block = list(range(20))
positions = block * 3  # three identical 20-position blocks
weights = Counter(positions)

assert len(positions) == 60
assert weights[0] == weights[19] == 3
assert weights[20] == 0
assert sum(weights.values()) == 60
```

Every one of the 20 covered positions has weight 3, and the exposure remains 60 positions, not 20.
A set-based collection would collapse the three copies to one and lose the multiplicity. If a
fourth block were drawn and the result trimmed to 60, the first three copies would remain exactly
as above. The fixed exposure means a false alert at position 0 has weighted count 3 and a
false-alert rate of `3 * 252 / 60 = 12.6` per year in this deliberately artificial draw.

### 8.4 Reproducibility

For identical input rows, frozen configuration and bootstrap seed, the score series, policy
identities, evaluation report and bootstrap draws are deterministic. The score cache key binds the
configuration hash, algorithm and package version, row count, date endpoints and a digest of every
produced point; the report carries its own provenance and policy/calibration hashes. A changed
window, normalization, cutoff, percentile or seed produces a different identity and must be
reported as a new result rather than compared silently with this one.
